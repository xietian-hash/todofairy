# 开发规范（微信小程序云开发，多端可扩展）

本文档是本项目的开发基线规范，适用于微信小程序、Web 端、桌面端（如 Electron/Tauri）等多端接入场景。  
若规范未覆盖的事项，必须先与用户确认后再实施。

## 1. 适用范围与关键原则（必须遵守）

1. **契约优先**：先定义接口契约（OpenAPI），再实现代码。  
2. **服务端兜底**：前端只负责展示与交互，鉴权、授权、校验、审计必须在服务端完成。  
3. **禁止前端直连数据库（红线）**：前端不得直接访问云数据库（包括查询）。所有数据读写统一走服务端接口。  
4. **可观测优先**：全链路必须可追踪（traceId），日志必须可定位用户、租户、设备与请求。  
5. **一致性优先**：统一目录结构、错误码、响应结构、命名规范、测试标准。  
6. **安全默认拒绝**：权限最小化、输入默认不可信、敏感信息不落端。  
7. **变更可回滚**：任何发布必须可灰度、可回滚、可审计。

---

## 2. 架构规范（多端统一接入）

### 2.1 总体架构

统一采用「客户端 -> HTTP API/BFF -> 云函数服务层 -> 云数据库/云存储」架构。  
说明：

- 小程序 / Web / 桌面端统一调用 HTTP API，不直接操作数据库。
- 云函数承担业务逻辑、权限判断、数据访问、审计日志。
- 云数据库与云存储作为数据层，仅允许服务端 SDK 访问敏感数据。

### 2.2 分层职责

- **接入层（API/BFF）**：鉴权、参数校验、限流、幂等、响应封装。
- **应用层（云函数）**：业务编排、事务处理、领域规则。
- **数据层（数据库/存储）**：持久化、索引、数据生命周期管理。

---

## 3. 技术选型与版本基线

### 3.1 客户端

- 微信小程序：小程序原生框架 + `wx.cloud` 能力（仅用于登录态与云能力接入，不直连数据库）。
- Web/桌面端：统一走 HTTP API，不绕过服务层。

### 3.2 服务端

- 云开发云函数（Node.js 运行时，优先使用官方稳定版本）。
- 采用分层代码结构：`controller -> service -> repository`（或等价分层）。

### 3.3 数据与存储

- 数据库：云数据库（文档型）。
- 文件：云存储（按业务目录分桶路径）。
- 缓存：按需引入（用于热点读与限流计数）。

### 3.4 接口规范

- 统一 RESTful 风格 + JSON。
- 对外接口统一版本前缀：`/api/v1/...`。

## 4. 仓库与工程结构

推荐目录（可按业务扩展）：

```text
.
├─apps/
│  ├─miniprogram/              # 小程序端代码
│  │  ├─pages/
│  │  ├─components/
│  │  ├─services/              # 仅封装 HTTP API 调用
│  │  ├─store/
│  │  └─utils/
│  ├─web/                      # Web 端应用
│  └─desktop-electron/         # Electron 桌面端应用
├─packages/
│  ├─shared/                   # 跨端共享类型、常量、工具
│  └─api-client/               # 多端统一 API 调用封装
├─cloudfunctions/              # 云函数
│  ├─gateway/                  # 统一 API 入口（可选）
│  ├─todo-create/
│  ├─todo-list/
│  └─shared/                   # 共享库（鉴权、日志、错误码、校验）
├─schemas/                     # 请求/响应与数据校验 schema
├─openapi/                     # 接口契约
├─scripts/                     # 构建、发布、检查脚本
└─.document/                   # PRD、UI规范、开发规范等
```

硬性要求：

- 客户端不得出现数据库 SDK 直接查询/写入代码。
- 云函数共享逻辑必须抽到 `shared`，禁止复制粘贴业务规则。

## 5. 编码规范

### 5.1 命名规范

- 变量/函数：小驼峰（`camelCase`）。
- 类型/类：大驼峰（`PascalCase`）。
- 常量：全大写下划线（`UPPER_SNAKE_CASE`）。
- 集合命名：业务名复数（如 `todos`）。
- 字段命名保持单一语义，禁止同名多义。

### 5.2 代码风格

- 统一使用 ESLint + Prettier。
- 提交前必须通过格式化与静态检查。
- 禁止提交注释掉的大段无效代码。

### 5.3 文件编码

- 所有文件必须为 **UTF-8（无 BOM）**。

---

## 6. 接口契约与响应规范（前后端统一）

### 6.1 契约来源（SSOT）

- OpenAPI 作为接口单一事实来源。
- 接口变更必须先改 OpenAPI，再改实现与调用方。

### 6.2 统一响应结构

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "xxxxxx"
}
```

### 6.3 分页结构

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "pageNo": 1,
    "pageSize": 20,
    "total": 120,
    "list": []
  },
  "traceId": "xxxxxx"
}
```

### 6.4 错误码规范

- 400：参数错误（ValidationError）
- 401：未登录（UnauthorizedError）
- 403：无权限（ForbiddenError）
- 404：资源不存在（NotFoundError）
- 409：冲突（唯一约束/并发冲突）
- 429：限流
- 500：系统内部错误

规则：

- 业务错误必须可预期并有稳定错误码。
- 不对外暴露堆栈信息。

---

## 7. 数据访问与一致性规范（重点）

### 7.1 前端访问红线

- 小程序/Web/桌面端 **禁止直接访问数据库（包含查询）**。
- 前端仅调用服务端 API。

### 7.2 服务端数据访问

- 所有数据库查询必须在云函数内完成。
- 查询字段、排序字段、筛选字段必须白名单化。
- 分页查询必须限制 `pageSize` 上限，防止全表扫描。

### 7.3 索引规范

- 新增查询场景必须同步评估索引。
- 高频条件查询必须建立单列或组合索引。
- 禁止在无索引条件下上线高频查询接口。

### 7.4 事务与幂等

- 涉及多文档一致性时使用事务。
- 创建/支付/提交类接口必须具备幂等机制（幂等键或去重键）。

### 7.5 删除策略

- 默认软删除（如 `isDeleted=true` + `deletedAt`）。
- 涉及合规清除要求的数据，走物理删除专用流程。

## 8. 安全规范

### 8.1 鉴权与授权

- 采用方案 A：登录成功后由服务端签发单 JWT（不使用 Refresh Token，不做主动下线）。
- JWT 有效期固定为 12 小时（`exp=12h`）。
- 客户端请求统一使用 `Authorization: Bearer <token>`。
- JWT 过期或无效时服务端返回 401，客户端自动重新登录并重发原请求（`http.js` 内置 401 自动重登机制：清除旧 token → 调用登录接口获取新 token → 用新 token 重发原请求，仅重试一次；并发请求通过登录锁防止重复登录）。
- 每个受保护接口必须校验用户身份与操作权限（RBAC/ABAC）。
- 严禁仅依赖前端按钮隐藏实现权限控制。

### 8.2 输入校验

- 所有接口入参必须做 schema 校验。
- 对字符串、时间、枚举、分页参数做严格边界控制。

### 8.3 敏感信息

- 密钥仅存环境变量，不写入代码库。
- JWT 签名密钥必须定期轮换，至少每 90 天轮换一次（紧急泄露事件需立即轮换）。
- 日志禁止打印密码、token、手机号完整值等敏感信息。

### 8.4 Web/桌面额外要求

- 配置 CORS 白名单（按环境区分）。
- 校验 `Origin` / `Referer`（按安全策略启用）。

---

## 9. 性能与稳定性规范

- 生产环境所有 API 必须使用 HTTPS。
- 核心云函数开启预置并发或等效措施，降低冷启动影响。
- API 必须配置限流策略（按用户/IP/设备维度之一或组合）。
- 客户端重试采用指数退避，禁止无限重试。
- 关键读接口可使用缓存，但必须设置过期与失效策略。
- 任一接口超时/失败需返回可识别错误码，不得静默失败。

---

## 10. 可观测性与审计规范

### 10.1 日志规范

- 全链路贯穿 `traceId`。
- 结构化日志字段至少包含：`timestamp`、`level`、`traceId`、`userId`、`action`、`durationMs`、`result`。

### 10.2 告警规范

- 对 5xx 错误率、接口耗时、限流触发率、函数异常退出设置告警。
- 告警需关联负责人和处理流程（值班/升级）。

### 10.3 审计规范

- 关键操作（创建、删除、权限变更、状态变更）必须记录审计日志。

---

## 11. 测试与质量门禁

### 11.1 必测范围

- 单元测试：核心业务函数、权限判断、参数校验。
- 集成测试：API 到云函数到数据库链路。
- 回归测试：核心用户路径（登录、创建、查询、更新、删除）。

### 11.2 安全与异常测试

- 越权访问、伪造身份、非法参数、重复提交、并发冲突、限流命中必须覆盖。

### 11.3 发布门禁

- 未通过测试/静态检查/契约校验不得发布。

---

## 12. 发布、灰度与回滚规范

### 12.1 环境隔离

- 强制 `dev / test / prod` 三环境隔离。
- 配置、密钥、数据、告警策略按环境独立管理。

### 12.2 发布流程

1. 合并前通过 CI 检查。  
2. 先发布测试环境并完成回归。  
3. 生产环境灰度发布（按流量或用户分层）。  
4. 观测通过后全量发布。

### 12.3 回滚流程

- 保留最近稳定版本函数与配置快照。
- 出现严重故障时，按预案一键回滚到上一稳定版本。

---

## 13. 文档联动与变更管理

- 代码功能变更后，必须同步更新以下文档（位于 `.document/`）：
  - PRD（需求与用户故事）
  - UI规范（交互或视觉变更时）
  - 接口契约（OpenAPI）
  - 本开发规范（若新增约束或例外）
- 变更说明需包含：改动点、影响面、风险、回滚方式。

---

## 14. 禁止事项清单（必须执行）

1. 禁止前端直接访问云数据库（含查询）。  
2. 禁止把密钥、token、账号密码写入仓库。  
3. 禁止绕过服务端权限校验。  
4. 禁止无索引高频查询上线。  
5. 禁止未评估风险直接在生产环境修改关键配置。
